# Windows 定时提醒客户端设计说明

## 设计概述

本项目是一个仅面向 Windows 的桌面定时提醒客户端，核心目标是稳定管理多条周期性提醒，并通过托盘常驻、本地持久化、系统通知和音频播放形成完整闭环。

## 模块划分

### 1. 存储层

- `Database`：负责 SQLite 连接、建表与基础数据库访问。
- `ReminderRepository`：负责提醒数据的增删改查。
- `SettingsRepository`：负责应用设置的读取与保存。

### 2. 领域层

- `Reminder`：描述提醒的业务实体与运行时字段。
- `AppSettings`：描述开机自启、自动提醒等应用级设置。
- `ReminderRuntimeState`：运行状态枚举，包含 `not_started`、`running`、`paused`。
- `ReminderPhase`：轮次阶段枚举，包含 `reminder`、`break`。

### 3. 服务层

- `ReminderService`：封装提醒创建、编辑、删除、启动、暂停、重置与批量控制。
- `ReminderScheduler`：根据当前轮次推进倒计时与状态切换。
- `AudioService`：负责播放自定义音频或回退默认提示音。
- `NotificationService`：负责托盘通知等提醒反馈。
- `AutostartService`：负责 Windows 开机自启配置。

### 4. 界面层

- `MainWindow`：展示提醒列表并提供批量操作入口。
- `ReminderDialog`：用于新建和编辑提醒。
- `SettingsDialog`：用于配置开机自启与自动提醒。
- `TrayController`：管理托盘图标、菜单与退出行为。

## 运行状态设计

### 1. 运行状态

- `not_started`：未启动。
- `running`：运行中。
- `paused`：已暂停。

### 2. 当前阶段

- `reminder`：提醒倒计时阶段。
- `break`：休息倒计时阶段。

### 3. 状态流转规则

1. 提醒启动后进入 `running`。
2. 倒计时每秒推进一次。
   - 提醒阶段归零后切换到 `break`。
   - 休息阶段归零后切换回 `reminder`。
3. 重置后恢复为提醒阶段初始时间，并置为 `not_started`。
4. 暂停后保留当前剩余时间，状态变为 `paused`。
5. 编辑运行中的提醒后，按新配置重置并回到 `not_started`。
6. 删除提醒后从本地存储中永久移除。
7. 程序退出前统一重置全部提醒并保存配置。

## 数据持久化设计

### reminders

- `id`：主键。
- `name`：提醒名称，要求唯一。
- `reminder_interval_minutes`：提醒间隔，单位分钟。
- `break_interval_minutes`：休息间隔，单位分钟。
- `music_path`：本地音频文件路径，可为空。
- `enabled`：是否启用。
- `runtime_state`：当前运行状态。
- `current_phase`：当前轮次阶段。
- `remaining_seconds`：当前轮次剩余秒数。
- `created_at`：创建时间。
- `updated_at`：更新时间。

### app_settings

- `settings_key`：固定为 `1`。
- `launch_at_startup`：是否启用开机自启。
- `auto_remind_on_launch`：启动后是否自动开始全部已启用提醒。
- `updated_at`：更新时间。

## Windows 集成设计

### 1. 托盘常驻

通过 `QSystemTrayIcon` 提供托盘图标与快捷菜单。主窗口关闭时默认最小化到托盘，不直接退出程序。

### 2. 开机自启

通过 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 写入启动项，实现当前用户级别的自启动能力。

### 3. 自动提醒

启动时读取 `AppSettings.auto_remind_on_launch`：

- 若托盘可用，则自动开始全部已启用提醒并隐藏主窗口。
- 若托盘不可用，则自动开始全部已启用提醒并保持主窗口可见。

### 4. 提醒反馈

- 优先使用 `QSystemTrayIcon.showMessage` 进行桌面通知。
- 音频播放使用 `QMediaPlayer + QAudioOutput`。
- 音频播放失败时回退到 `QApplication.beep()`。

### 5. 退出策略

- 关闭主窗口仅隐藏到托盘。
- 只有明确执行“退出程序”时才真正退出。
- 退出前统一保存配置并重置提醒状态。

## 图标与打包

- 图标资源统一放在 `assets` 目录。
- `app_icon.svg` 为设计源文件。
- `app_icon.png` 用于预览与通用位图场景。
- `app_icon.ico` 作为 Windows 应用图标与打包图标，包含多尺寸位图。
- `scripts\generate_app_icon.py` 用于从 `svg` 生成 `png` 与 `ico`。

## 打包设计

- 采用 `PyInstaller` 单目录方案，目标平台为 Windows。
- 入口脚本为 `src\reminder_client\main.py`。
- 通过 `--paths src` 解决源码路径导入问题。
- 通过 `--add-data` 打包图标等静态资源。
- 运行数据目录固定在 `LOCALAPPDATA\ReminderClient`。
- 用户音频作为外部文件引用，不跟随程序打包。

## 测试建议

- 核心业务逻辑通过单元测试覆盖状态流转、仓储访问、设置读写与启动行为。
- UI 通过 `pytest-qt` 覆盖主窗口、提醒弹窗和系统设置交互。
- 提交前至少执行 `python -m compileall src scripts`，并检查文档是否存在乱码。
## 6. 视觉识别提醒

### 6.1 数据结构
- `Reminder.visual_reminder_enabled`：是否启用视觉识别
- `Reminder.visual_music_path`：视觉识别结果需要补播时使用的独立音频
- `AppSettings.ark_base_url`：Ark Responses 调用地址
- `AppSettings.ark_api_key`：Ark API Key
- `AppSettings.ark_model_name`：Ark 模型名
- `vision_decision_logs`：记录每次模型调用的日志表

### 6.2 运行流程
- 到点后先走原有定时提醒音频
- 延迟 60 秒后由 `VisionDecisionService` 抓拍摄像头照片
- 使用 `ArkVisionClient` 发送 `input_image + input_text` 请求
- 只允许返回三种结果：
  - `用户已离开电脑前`
  - `用户未离开电脑前`
  - `识别失败`
- 返回 `用户未离开电脑前` 时，只补播一次视觉提醒音频
- 返回 `用户已离开电脑前` 或 `识别失败` 时，不再补播音频
- 只要发生模型调用，就写入 SQLite 日志
- 主窗口新增“日志”按钮，点击后以弹窗形式查看最近的视觉调用记录和详情

### 6.3 接口契约
- `ReminderService.schedule_visual_decision(reminder_id)`：安排一次 60 秒后的视觉判定
- `ReminderService.cancel_visual_decision(reminder_id)`：取消待执行的视觉判定
- `ReminderService.test_visual_decision(payload)`：用于编辑页测试按钮，直接执行一次视觉判定
- `VisionDecisionService.evaluate(reminder, settings)`：执行抓拍、调用模型、归一化结果和写日志
